# Five-minute demo recording script

Aim for 4 minutes 45 seconds. Record the real local app with the supplied synthetic dataset. Agent Assist gets the detailed demonstration; the other five use cases get a brief evidence-led overview. This is not six exhaustive demos. The six use cases are Agent Assist, Next Best Action, channel comparison, agent routing, post-call summary and QA coaching. The four layers are the C360 foundation, questions with evidence, shared features and employee-reviewed assistance.

## Before recording

1. Start the existing environment from the repository folder: `.\.venv\Scripts\python.exe -m streamlit run app.py`. Open `http://127.0.0.1:8501`. Do not rebuild the data or retrain models for the recording.
2. If the login screen appears, use your own configured supervisor account. A supervisor can open the three demo cases and aggregate questions. Keep the login and password entry out of the recording. Without a configured account, the app explicitly labels access as demo access; do not describe that as authenticated access.
3. Rehearse the cases below. Keep **Use snapshot time for demonstration** checked and the decision time at `2026-09-28T15:00:00+00:00`. This is a dated simulation, not current contact permission. Confirm each case loads and the expected call/audio is available before recording.
4. Prepare separate browser tabs for the app, `docs/architecture.png` and `reports/implementation_checks.json` in the private repository. Increase browser zoom enough for text to be readable. Close notifications and unrelated windows.
5. Use an installed screen recorder with microphone narration. Record the app window at 1080p if possible. Do a ten-second sound test. Rehearse once with a timer; leave model loading and long scrolling out of the final take.
6. Optional: preflight **Draft with the locally fine-tuned model** in **Review assistance**. Use it only if the button appears and succeeds. Skip this click during the video if loading is slow. The deterministic brief is a working fallback. Do not click the paid **Draft AI summary from approved facts** button.

## Avoid inaccurate claims

- Say "pretrained Whisper", "team-trained hardship classifier" and "locally fine-tuned Qwen adapter". We did not train a language model from scratch.
- Say "all six employee-reviewed workflows are implemented". Do not claim all six are optimal, independently validated or production-ready.
- Do not call QA statuses a compliance score. Some issue detectors have low or zero recall; an employee still reviews every item.
- The channel output may have no ready recommendation. Show the missing prerequisites rather than selecting an unsupported winner.
- The local model's exact-value evaluation measures its narrow output format, not general financial reasoning. Do not describe the 468/468 result as general accuracy.
- Use the latest report's test count if you speak it. It was 136 passing tests when this script was prepared, and later benchmark changes can alter it. The script deliberately avoids a fixed spoken count.
- Do not claim a measured 30% time saving, hidden benchmark accuracy or successful paid integration. The combined runner now includes all 50 questions. The extra set produced 12 answers and three scope refusals without errors, but there is no official extra score. Generated answers still need semantic assessment. Final submission status should be described only after the team submits the form.
